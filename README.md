# Lotto 6/45 V4.0 — 研究治理平台

V4.0 在 V3.8 稳健研究引擎之上增加统一研究治理：冻结选型数据指纹、严格手动追加下一期开奖、追加式实验事件档案、前瞻锁定恢复、按开奖期配对统计及模型晋升门槛。原 V3.6.1 / V3.7 / V3.8 研究页面继续保留。

## V4.0 新增能力

1. **双层数据指纹**：完整历史数据指纹与固定选型区间指纹分开。新增第1089期之后的开奖，不再自动使截至第1088期的 V3.8 冻结选型失效。
2. **严格追加**：仅能追加当前最大期号的下一期；校验六个不重复主号码、Bonus、开奖日期；跳期或冲突记录拒绝写入；完全相同的重复记录幂等处理。
3. **研究事件档案**：模型快照、手动追加事件、前瞻锁定记录作为追加式 JSON 事件保存，可导出和恢复。
4. **前瞻锁定恢复**：可从事件档案恢复原锁定号码，或从已保存模型快照为下一期生成新的锁定。
5. **按开奖期统计**：模型与随机基准先按每期开奖聚合，再进行配对区块 Bootstrap，避免把同一期的多注号码当作独立样本；三项主要指标进行 Holm 多重比较校正。
6. **模型晋升门槛**：至少100个前瞻开奖期，平均命中、单注3+率、整批3+率三个点估计均高于随机，三个区块 Bootstrap 95%置信区间下限均大于0，且 Holm 校正 p 值均小于0.05，才允许进入晋升候选。该规则是研究治理门槛，不代表预测保证。

## V4.0 实验档案持久化

- 不配置 Token 时，可在「V4.0研究治理」页面下载和恢复 V4.0 JSON 事件档案。
- 可选地在 Streamlit Secrets 配置 GITHUB_RESEARCH_TOKEN（Fine-grained Token，只授予本仓库 Contents 读写权限）。应用只将研究事件写入独立的 research-data 分支，不写入 main 的开奖记录。
- GitHub 持久化用于保存用户自己的研究事件和锁定档案，不用于获取任何彩票开奖数据。
- Token 不得提交到仓库，也不要粘贴在聊天中。

## 数据政策（继续强制执行）

- **禁止连接韩国 Lotto / 동행복권 官方网站及其 API。**
- 禁止自动爬取、定时同步、第三方镜像拉取或后台开奖数据刷新。
- 仅分析用户手动导入的 CSV、XLSX、XLS，或仓库 data/lotto645.csv 中由用户手动维护的数据。
- 不要覆盖 data/lotto645.csv、data/sync_status.json 或 data/experiment_ledger.json。
- 统计与测试结果不自动意味着彩票具有可预测性；公平独立开奖下，所有固定六号码组合的理论概率相同。

# Lotto 6/45 V3.8 — 稳健研究与前瞻验证平台

V3.8 在保留 V3.6.1 / V3.7 功能的基础上，增加多窗口稳健研究、预测与组合结构分轨评价、空间均衡参数设计、优胜候选多种子复核、前瞻锁定记录，并修复完整研究包对 V3.7 / V3.8 实验结果的导出遗漏。

## 固定数据政策

- **禁止连接韩国 Lotto / 동행복권 官方网站及其 API。**
- 禁止自动爬取、定时同步、第三方镜像拉取或后台开奖数据刷新。
- 仅分析用户手动导入的 CSV、XLSX、XLS，或仓库 `data/lotto645.csv` 中由用户手动维护的数据。
- `sync_data.py` 是安全停用入口，不执行网络访问。
- 不要把回测明细 CSV 当成开奖历史数据。

## V3.8 设计

### A. 稳健模型研究引擎

| 项目 | V3.8 设置 |
|---|---:|
| 可调模型 | 7种；均匀随机为配对基准 |
| 参数配置预算 | 500组唯一配置 |
| 参数空间 | 每个模型分别进行 Latin-hypercube 空间均衡采样 |
| 初筛 | 3个分散窗口 × 每窗口4期；1组随机种子，降低计算成本 |
| 优胜候选 | 每个模型前1组进入复核 |
| 复核 | 3组随机种子 |
| 优胜候选复核 | 3个分散、互不重叠窗口 × 每窗口6期 |
| 外层验证 | 3折 × 每折12期 |
| 每期每模型 | 10注 |

内层每个目标期的模型特征只使用目标期之前的数据。外层每折先在其训练前缀内完成500组初筛和优胜候选复核，再使用该折未来12期进行回溯式样本外评估。

### B. 预测表现与组合结构分轨

预测综合分只包含：
1. 相对随机的平均命中数差；
2. 相对随机的单注3+率差；
3. 相对随机的整批3+比例差；
4. 跨内层窗口稳定性。

组合结构综合分单独包含：
- 相对随机的号码覆盖差；
- 相对随机的组间重号减少。

覆盖率和重号减少不参与预测综合分。系统不会仅因某个候选相对排名第一就宣称它具有预测优势；如果主要命中指标没有同时超过随机，页面会明确显示“尚无预测优势证据”。

### C. 已审阅历史窗口保护

V3.7 实验已经审阅第1089—1148期外层验证和第1149—1248期独立保留测试。为了不把已经看过的结果重新包装成新的测试，V3.8 默认只使用第1—1088期作为历史稳健研究区间。

- V3.8 当前回溯结果不是新的独立保留测试。
- 第1089—1248期可作为已知历史，在生成未来候选时使用；不得再次称为未使用测试区间。
- `data/experiment_ledger.json` 记录已审阅区间，更新代码时必须保留该文件。

### D. 前瞻锁定

V3.8 可将冻结的最终研究候选应用于当前全部已知手动历史，生成下一期：
- 模型10注 × 3组随机种子；
- 均匀随机基准10注 × 3组随机种子。

锁定文件记录目标期号、锁定时间、历史数据指纹、模型参数与随机种子。目标期开奖号码在锁定后手动导入时，应用可以计算逐注命中与分组汇总。

**必须在目标期开奖前下载并保存锁定文件。** 应用只能检查目标期号晚于锁定时的历史末期，不能独立证明用户下载时间早于开奖公布时间；因此前瞻结果仍需保留锁定原件供审计。

## 自动测试

```bash
python -m compileall -q .
python -m unittest discover -s tests -v
```

升级包是对现有 V3.7 仓库的补丁，不包含所有未修改的依赖模块。因此，`tests/` 应在把补丁覆盖/新增到完整仓库后，从完整仓库根目录运行；仅在解压补丁目录中单独运行测试会因缺少未修改的 V3.7 模块而无法导入。交付报告记录了完整工作树中的测试结果。合成数据测试验证代码逻辑，不证明任何模型拥有未来预测优势。真实历史数据的500组基准试跑约29.9秒；云端耗时会受运行资源影响。

## 统计解释边界

公平且独立开奖下，每一个固定六号码组合的头奖概率相同。历史回测、参数排名、Pareto 前沿、号码覆盖和前瞻锁定记录不自动等于预测优势。只有事先锁定的未来预测、足够长的前瞻样本和适当的不确定性分析，才可用于进一步评价模型表现。
