# V8.5 — Probability-weighted low-overlap portfolio research

V8.5 combines V5's first-order number-inclusion marginals with the V8.4 ten-ticket low-overlap graph design.

## Construction

1. For each historical target draw, fit V5 on strictly earlier draws only and obtain 45 marginal inclusion probabilities summing to six.
2. Apply the V8.1 dependent-rounding mechanism to 10 times each marginal probability. Each integer batch count is floor(10*p_i) or ceil(10*p_i), the sum is exactly 60, and randomized rounding is unbiased across seeds.
3. Allocate those same integer quotas to ten six-number tickets while requiring any two tickets to share at most one number. When the rounded degrees are 15 twos and 30 ones, use the exact V8.4 graph-17 structure. Other feasible integer degree patterns use a backtracking incidence allocator; infeasible patterns fail explicitly rather than silently relaxing the overlap rule.
4. Compare V5 sequential weighted sampling, V8.0 conditional-Bernoulli sampling, V8.1 quota allocation, V8.5 quota-plus-low-overlap allocation, and a uniform-random ten-ticket control.

The V8.1 and V8.5 methods use the same per-target randomized appearance quotas, so their paired difference isolates row allocation and overlap constraints rather than a different number-count draw.

## Evaluation

- Run a 500-draw strictly prequential evaluation on the latest available manual history; every target's feature rows and fitted model use only earlier draws.
- Primary endpoint: whether at least one of ten tickets hits 3+ numbers.
- Secondary endpoints: mean hits, per-ticket 3+/4+, batch 4+, best-ticket hits, coverage and pairwise overlap.
- Paired moving-block bootstrap uses 10-draw blocks and Holm adjustment across the four primary V8.5 comparisons.

## Evidence boundary

The 752–1251 target window is retrospective and has already been examined in previous V7/V8 research. Strict chronological replay prevents target leakage, but does not turn this period into an untouched holdout or prospective test. The V5 predictor's future signal is not established. Therefore V8.5 is a research comparison only: it never changes the production picker, does not write data/lotto645.csv, does not create or replace any forward lock, and does not access official lottery sites or APIs.
