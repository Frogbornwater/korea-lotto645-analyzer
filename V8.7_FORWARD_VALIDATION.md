# V8.7 — Immutable prospective validation protocol

## Why this stage is different

V8.6 found that temperature scaling can modestly improve historical probability calibration, but did not establish that V5 ranks the winning numbers better than uniform random. V8.7 therefore stops tuning against the already inspected 752–1251 window and establishes a prospective, auditable test.

## Pre-draw lock

The manual workflow has two explicit operations: `prepare` and `score_latest`. It is never triggered automatically by a push.

For `prepare`:

1. Read only `data/lotto645.csv`, which must have a complete sequence from draw 1.
2. Set target draw to latest manually imported draw + 1.
3. Refuse creation if any `draw_{target}*.json` commitment already exists or if the target-specific Git branch exists.
4. Fit the unchanged V5 engine with training window 500, minimum history 180 and ridge alpha 1.
5. Freeze four ten-ticket portfolios: V5 raw probabilities, V8.1 batch quotas, V8.5 low-overlap allocation, and a uniform-random control. Also freeze the 45 V5 inclusion probabilities, ranked numbers, seeds and full normalized pre-draw history fingerprint.
6. Upload the candidate archive and commit both candidate JSON and hash manifest to a unique branch `forward-locks/draw-{target}-v87`. The main branch and production app are not modified.

The workflow requires the explicit confirmation input `LOCK`. At the current repository state the latest manual data is draw 1251, and draw 1252 is already committed by `draw_1252_research.json`; therefore V8.7 must refuse to create another draw-1252 lock. Once the user manually imports draw 1252, the next target becomes 1253.

## Post-draw scoring

After the user manually adds a result to the CSV, select `score_latest` with confirmation `SCORE`. The workflow retrieves the pre-draw candidate archive from its immutable branch (or the pre-existing legacy V8.x archive), verifies file and canonical hashes, and requires the CSV's latest draw to equal the lock target.

For V8.7 locks, the entire normalized pre-draw history fingerprint must match exactly. For the legacy 1252 archive, the ZIP, embedded JSON, raw hash, canonical payload hash and final pre-draw draw fields are verified; the legacy manifest's old history-hash serialization is not recomputed.

The score records, by strategy, every ticket's hit count, hit distribution, mean hits, 3+/4+ rates, batch 3+/4+ outcome, best ticket, total hits and number coverage. V5's 45-dimensional probability vector is also scored with Brier and LogLoss, and Top-6/10/15 hit counts are recorded.

The score is committed to a separate immutable branch `forward-lock-scores/draw-{target}-v87`. It does not rewrite the candidate lock or main branch.

## Timing and inference rules

- The public Git commit timestamp is checked against the target draw date in Asia/Seoul.
- A commit on an earlier calendar day is marked date-verified. A same-day commit is explicitly unverified because the manually supplied CSV contains a date but no draw time.
- A missing draw date or missing commit timestamp cannot be described as verified pre-draw.
- One draw's outcome is descriptive only. It is not a statistically powered test of superiority; accumulate multiple prospective draws before making model changes.
- The main-ticket odds remain determined by the lottery's fair random draw. V8.7 does not claim a historical model can change those odds.

## Existing draw 1252 protection

The existing `data/forward_lock_commitments/draw_1252_research.json` and its Actions archive are consumed read-only. The protocol includes a legacy archive verifier so the existing 1252 tickets can be scored after draw 1252 is manually imported. It must never create or replace another 1252 lock.

## Commands

    python -m py_compile v87_forward_protocol.py scripts/v87_forward_protocol.py
    python -m unittest discover -s tests -p "test_v87_forward_protocol.py" -v

Create a new lock (only after reviewing the latest manually imported draw and existing commitment files):

    python scripts/v87_forward_protocol.py prepare

Score a V8.7 lock after manually importing the target result:

    python scripts/v87_forward_protocol.py score --candidate <candidate.json> --manifest <manifest.json> --commit-timestamp-utc <Git-commit-time> --output <score.json>

Score the existing 1252 V8.x archive without modifying it:

    python scripts/v87_forward_protocol.py score-legacy --manifest data/forward_lock_commitments/draw_1252_research.json --archive <downloaded-1252-archive.zip> --output <score.json>

No official lottery site or API is accessed.
