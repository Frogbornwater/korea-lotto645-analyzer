# V8.9 — Prospective multi-draw cohort audit

## Purpose
V8.8 found no statistically significant retrospective advantage over random. V8.9 therefore does not tune model parameters. It aggregates only immutable single-draw scores from the V8.7 forward-lock protocol, creating a pre-registered prospective cohort comparison.

## Inclusion rules
A score is eligible only when:
- The pre-draw history fingerprint (or legacy endpoint check) is verified.
- The public commitment date is strictly earlier than the target draw date. Same-day locks are excluded because the CSV records a date, not the draw time.
- V5, V8.1, V8.5 and the same-draw uniform-random control all have complete strategy metrics.
- Each target draw appears exactly once. Duplicate target files fail closed.

Historical walk-forward replay is never mixed into the prospective cohort. A legacy draw-1252 lock can be included only if its date/timing status is verified and it contains all four comparable strategy groups; otherwise it is explicitly excluded.

## Primary endpoint and inference
Primary endpoint: whether at least one of ten tickets in a strategy portfolio hits 3+ main numbers.
For each target draw, compare each strategy with its own same-draw uniform-random control. The inferential unit is the draw, not individual tickets.
- One-sided exact paired McNemar/binomial test over discordant draw outcomes.
- Holm correction across V5, V8.1 and V8.5.
- Report paired wins/losses/ties, success rates and Wilson intervals.
- Mean hits and ticket-level 3+ rate are secondary descriptive outcomes.
- Minimum 100 eligible prospective draws is a reporting-readiness gate only; it is not a claim that 100 draws guarantee adequate power.

## Run locally or in a research workflow
After retrieving the immutable score JSON files from their per-draw score branches, place copies in a new, empty directory and run:

```bash
python -m py_compile v89_prospective_cohort.py
python -m unittest discover -s tests -p "test_v89_prospective_cohort.py" -v
python scripts/v89_prospective_cohort.py --scores-dir artifacts/v89/scores --output artifacts/v89/v89_cohort_report.json
```

The report refuses to overwrite an existing file. The module does not fetch results, does not access the official lottery site/API, does not edit history or lock files, and does not change the production picker or Streamlit app.
