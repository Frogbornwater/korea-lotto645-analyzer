# V9.0 — Prospective probability and ranking audit

## Purpose
V8.9 evaluates portfolio-level 3+ outcomes. V9.0 adds a separate audit of the V5 45-number marginal probability forecast and its Top-K ranking, using only immutable, date-verified prospective score reports. It does not tune parameters or change production.

## Eligibility
The cohort loader reuses V8.9's strict rules: verified pre-draw history fingerprint (or verified legacy endpoint), a commitment date strictly before the target draw date, complete strategy groups and no duplicate target draw. Historical replay and same-day unverified locks are excluded. Each eligible report must also contain V8.7's `v5_probability_metrics`.

## Metrics
- Per-draw Brier score and LogLoss, averaged across eligible draws. Lower is better.
- Top-6, Top-10 and Top-15 hit counts, averaged across draws. Higher is better.
- Uniform marginal reference uses p=6/45 for each number. Expected Top-K hits are K*6/45.
- Draw-level paired percentile bootstrap (10,000 replicates by default) reports 95% intervals for the mean difference from the uniform reference.

The uniform Brier and LogLoss references are calculated from six positives and 39 negatives at p=6/45. They are reference scores, not an alternative trained model.

## Important limitations
The current V8.7 score schema stores per-draw Brier/LogLoss and Top-K counts but does not retain the raw 45-dimensional probability vector in the score report. Therefore V9.0 cannot honestly produce reliability diagrams, calibration slope/intercept, or probability-bin calibration curves. Those require a future versioned score schema that stores the exact locked probability vector and its hash. V9.0 does not reconstruct or invent those values.

Bootstrap intervals are descriptive evidence summaries, not automatic proof of superiority. A confidence interval crossing zero is not evidence of improvement. Even a favorable retrospective-looking prospective cohort must be interpreted with its pre-registered endpoint and cohort size.

## Run
```bash
python -m py_compile v90_prospective_probability.py scripts/v90_prospective_probability.py
python -m unittest discover -s tests -p "test_v90_prospective_probability.py" -v
python scripts/v90_prospective_probability.py --scores-dir artifacts/v89/scores --output artifacts/v90/v90_probability_report.json
```

The output refuses to overwrite an existing report. This research module is offline-only, reads user-supplied score JSON files, does not access the official lottery website/API, and does not edit the history CSV, forward locks, Streamlit app, or production picker.
